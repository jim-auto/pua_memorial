# pua_memorial

東京の夜を舞台にした、ブラウザで遊べる会話シミュレーションゲーム。
相手の言葉や仕草を読みながら返答を選ぶと、会話の空気と結末が変わります。

## ゲームの特徴

- **4つの舞台**：渋谷・歌舞伎町・池袋・クラブ周辺。場所に合わせて会話とビジュアルが変化します。
- **8種類の相手**：性格や状況、初期ステータスがプレイごとにランダムで決まります。
- **最大6フェーズの会話**：声かけ → 会話1〜3 → 打診 → ルートに応じたホテル前確認。
- **10種類のエンディング**：連絡先交換、翌日の約束、ホテルへの各ルート、撤退やトラブルなどに分岐します。
- **集中力の使いどころ**：1プレイで2ポイント。相手を観察して手がかりを得るか、深呼吸でメンタルを回復するかを選べます。
- **返答の組み合わせ**：質問してから受け止めると会話がつながります。同じ調子を3回続けると、興味とノリは上がりにくくなります。
- **再挑戦と記録**：同じ相手・初期状態・反応の揺れを再現して再挑戦できます。発見したエンディングはブラウザに記録します。
- **反応を読む仕組み**：メンタルと観察力に加え、相手の警戒・興味・ノリ・時間の余裕が展開に影響します。同じ選択でも結果は一定ではありません。

## 遊び方

1. 場面と「相手の言葉」を読み、返答のボタンを選びます。
2. 必要な場面で「相手を観察する」か「深呼吸する」を使います。集中力は合計2ポイントで、ターンは進みません。
3. 選択後は相手の反応を読み、「会話を続ける」で次へ進みます。返答ごとに時間が進むため、短い返答や早めの連絡先交換も選択肢です。
4. 終了後は振り返りと各ターンの数値変化を確認できます。「同じ相手に再挑戦」で返しを比較するか、「新しい相手で遊ぶ」で別の出会いを試せます。

進行はブラウザのメモリ上で管理しています。ページを再読み込みすると最初から始まります。エンディング記録のみ `localStorage` に保存します。

## ローカルで起動

Node.jsとnpmを用意し、リポジトリのルートで実行します。

```bash
npm ci
npm run dev
```

ブラウザで **[http://localhost:3000/pua_memorial/](http://localhost:3000/pua_memorial/)** を開いてください。
`basePath` が設定されているため、URLには `/pua_memorial/` が必要です。
通常の起動・プレイにAPIキーや環境変数の設定は不要です。

## ビルド・静的配信

```bash
npm run build
npm run serve:out
```

`build` はNext.jsの静的サイトを `out/` に出力し、配信用の `docs/` へコピーします。
プレビューでは、ターミナルに表示されたURLに `/pua_memorial/` を付けて開いてください。

GitHub Pagesで公開する場合は、リポジトリの **Settings → Pages** で配信元を `main` ブランチの `/docs` に設定します。
サイトを更新するときは、再ビルドした `docs/` もコミット・pushしてください。
リポジトリ名や配信先のパスを変える場合は、`next.config.js`、`scripts/copy-out-to-docs.mjs`、`components/Game.tsx` 内の `/pua_memorial` に関する設定も合わせて更新します。

## 技術・構成

Next.js 15（App Router）・React 19・TypeScript・Tailwind CSSを使用しています。
ゲームはクライアント側で動作し、静的サイトとして配信できます。

| パス | 役割 |
| --- | --- |
| `app/` | ページ、レイアウト、共通スタイル |
| `components/Game.tsx` | ゲーム画面、反応の表示、エンディング記録 |
| `lib/game.ts` | 会話の進行、集中力、状態変化とエンディングの判定 |
| `tests/game.test.mjs` | 分岐・再現性・リソース制限の自動テスト |
| `data/scenario.ts` | 相手プロフィール、会話、選択肢、エンディングの定義 |
| `public/assets/visual-novel/` | 場所・反応別のゲーム画像 |
| `assets/readme/hero.png` | README冒頭のヒーロー画像 |
| `scripts/` | 静的出力のコピー、ゲーム画像の生成 |
| `docs/` | GitHub Pages用のビルド成果物（自動生成） |

会話や相手を追加・調整するときは `data/scenario.ts`、判定は `lib/game.ts`、画面は `components/Game.tsx` を編集します。

変更後の確認：

```bash
npm test
npx tsc --noEmit
npm run build
```

## 画像素材

ゲーム用の画像は同梱済みです。画像が読み込めない場合は、背景・人物のレイヤー画像、組み込みSVGの順にフォールバックします。
ファイル名と推奨サイズは[素材README](public/assets/visual-novel/README.md)、生成用プロンプトは[IMAGE_GENERATION_PROMPTS.md](IMAGE_GENERATION_PROMPTS.md)を参照してください。

ゲーム画像の生成スクリプトを実行する場合：

```bash
npm run generate:art
```

既存画像はスキップされます。再生成する場合は `FORCE_ART=1 npm run generate:art` を使用します。
このスクリプトは外部のPollinations画像生成サービスへ接続するため、通信環境やサービスの稼働状況に依存します。
READMEのヒーロー画像は、組み込みの画像生成ツールで別途作成したものです。
